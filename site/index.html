lms-solidity verifies LMS and HSS signatures (RFC 8554, with NIST SP 800-208's SHA-256/192 sets) in pure Solidity. Keys and signatures use the RFC's byte encodings unchanged, so anything an RFC 8554 implementation produces, including HSMs and libraries such as hash-sigs and hsslms, verifies as is.

import {LMS} from lms-solidity/LMS.sol;
bool ok = LMS.verifyHSS(publicKey, message, signature); // RFC 8554 §6.3
bool ok2 = LMS.verifyLMS(publicKey, message, signature); // Algorithms 6, 6a
// then record the leaf q as spent: LMS is stateful

What it verifies

Each leaf is a one-time key, so the signer must keep a counter and never reuse it, and the verifying contract must record every leaf it accepts. In return verification is cheap and the only assumption is the hash function.

Every malformed input, of any kind, makes verification return false; nothing reverts on attacker-controlled input. The compiler is pinned (solc 0.8.37, via-IR, 200 optimizer runs) so a tag always rebuilds the same bytecode, the bytecode the proofs cover.

Unaudited. This is new cryptographic code, released as v0.1.0. It is tested against its standard's vectors and independent implementations, and parts of it are formally proven, but no third party has reviewed it. Use it at your own risk.
LMS is stateful. Signing twice with one leaf lets an attacker forge. This library verifies signatures; it cannot know which leaves a signer has used. A contract that grants authority on an LMS signature must record each leaf it accepts (the bottom tree's q, under that tree's public key) and refuse it the second time. For the same reason it does not implement IPQVerifier, whose bare yes/no answer suits only stateless schemes.

Gas

Single-tree verification with a 32-byte message, measured by forge test (including copying the call data). Tree height adds only about 1,000–2,000 gas per level. The RFC's two-level HSS test cases cost 3.4M (W8) and 2.3M (W4).

How it is checked

13 tests in forge test, and a halmos proof job, run in CI on every push. CI proves 28 of the 30 lemmas; the two w = 1 checksum lemmas need more memory than a hosted runner has and are run locally. PROOF.md states exactly what is proven, what is argued by hand, and what is only tested.

The RFC's own test cases

Both test cases of RFC 8554 Appendix F verify, and CI re-extracts them from the RFC text and compares them byte for byte.

Two independent implementations

Every committed vector, 47 in all, verifies under hsslms and under a line-by-line Python transcription of the RFC, and fails under both once its message changes. They cover every LM-OTS set at both widths, heights 5–25 and HSS with 1–3 levels.

Proofs with teeth

Halmos proves each step (checksum and digits, every chain, the tree climb, header and length parsing) equal to a Solidity transcription of the RFC for all inputs. Seven planted bugs are each caught by their lemma. PROOF.md says what is proven and what is argued.

Quickstart

Run the tests and the proofs

git clone --recursive https://github.com/skalenetwork/lms-solidity
cd lms-solidity
forge test --match-test test_rfc8554TestCasesVerify -vv
forge test
halmos --match-contract LMSEquivalence --loop 300 --solver-timeout-assertion 0

Install

# Foundry
forge install skalenetwork/lms-solidity@v0.1.0
# remappings.txt
lms-solidity/=lib/lms-solidity/src/

See the README for the full API.

Part of a family

One Solidity library per post-quantum signature scheme, each tested against its own standard and each stating exactly what its proofs cover.
